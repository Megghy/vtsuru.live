# 用户自定义页面全面改进计划

> 审查日期：2026-07-20
>
> 适用范围：`src/apps/user-page`、用户页公开入口、用户页编辑器及其直接依赖
>
> 文档状态：已实施
>
> 相关文档：`DESIGN.md`、`TODO.md`、`PROGRESS.md`、`CONTRIBUTING.md`

## 1. 目标

本计划用于统一记录用户自定义页面当前存在的功能、稳定性、安全性、性能、可访问性和视觉体验问题，并给出可以直接执行的改造顺序与验收标准。

改造遵循以下原则：

1. 先保证公开页面行为正确、安全、可恢复，再处理视觉细节。
2. schema、编辑器和渲染器必须使用同一份能力定义，禁止三处分别维护。
3. 公开页面只加载当前实际使用的模块和数据，避免为编辑能力付出运行时成本。
4. 访客只看到友好的错误信息，内部诊断信息仅进入日志或所有者视图。
5. 原生 CSS 使用 `--vtsuru-*` 语义变量，Naive UI 组件继续使用 theme overrides 和组件 props。
6. 默认兼顾窄屏、键盘操作、明暗主题和减少动态效果偏好。
7. 每一阶段完成后独立验证，不把大量风险集中到一次发布。

### 2.3 优先级定义

| 优先级 | 含义 | 处理要求 |
| --- | --- | --- |
| P0 | 会导致错误展示、安全边界失效、关键功能失真或明显空白 | 第一阶段完成，阻断新功能扩展 |
| P1 | 会导致竞态、配置漂移、重复请求、体积增长或维护成本持续扩大 | P0 后立即处理 |
| P2 | 主要影响移动端、可访问性、视觉一致性和编辑效率 | 在核心稳定后集中处理 |
| P3 | SEO、可观测性和长期体验增强 | 按收益和发布节奏安排 |

## 3. P0：正确性与安全边界

### UP-001 合并用户页配置请求

- 状态：已完成
- 现状：`src/apps/layouts/UserLayout.vue` 与 `src/apps/user/pages/UserPageEntryView.vue` 分别请求同一份用户页配置。
- 影响：首屏产生重复网络请求，两个组件可能得到不同时间点的数据，错误处理和缓存行为也不一致。
- 方案：由路由入口或布局层负责一次加载，通过 composable 或 provide/inject 向标题栏和页面主体提供统一状态。缓存键至少包含 `userId` 与 `pageSlug`。
- 验收：一次公开页面导航只发起一次配置请求；标题、页面主体和错误状态使用同一份响应；切换用户或页面时正确失效。

### UP-002 建立明确的公开页状态机

- 状态：已完成
- 现状：`src/apps/user/pages/UserPageEntryView.vue` 在请求失败或配置异常时可能回退到旧版用户主页，访客无法区分“未配置”和“加载失败”。
- 影响：服务异常会被伪装成无自定义页面，错误难以发现，也可能展示与用户预期不同的内容。
- 方案：统一为 `idle`、`loading`、`not-found`、`error`、`ready` 五种状态。仅确认未配置自定义页面时进入旧版主页；网络错误和解析错误显示独立失败状态与重试入口。
- 验收：断网、500、404、无配置、非法配置分别呈现正确状态；重试不刷新整页；访客不看到 schema 内部路径或堆栈信息。

### UP-003 修复 ImageGallery 配置漂移

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/ImageGalleryBlock.vue` 读取或硬编码了 `framed`、`showArrow`、`loop`、`draggable` 等配置，但 schema、编辑器和渲染器没有完整对齐。
- 影响：编辑器中的设置可能不生效，或运行时存在编辑器无法配置的隐藏行为。
- 方案：确认画廊最终支持的最小配置集，删除无效字段；剩余字段统一写入 block registry，由 schema 默认值、编辑表单和公开渲染共同消费。
- 验收：每个保留字段都能在编辑器中修改、保存、重新加载并准确渲染；不存在仅在组件内部生效的硬编码配置。

### UP-004 让 MusicPlayer 的 compact 配置真实生效

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/MusicPlayerBlock.vue` 声明并读取 `compact`，但最终布局没有完整体现该配置。
- 影响：用户切换紧凑模式后看不到预期变化，配置成为无效项。
- 方案：若紧凑模式有明确使用场景，则重新定义紧凑布局的尺寸、控件和文本规则；否则从 schema、编辑器和渲染器中彻底删除该字段。
- 验收：配置不存在虚假开关；保留时桌面和移动端都有稳定且可辨认的紧凑布局。

### UP-005 修复直播持续时间停止更新

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/LiveStatusBlock.vue` 使用包含 `Date.now()` 的 computed 计算直播时长，但没有响应式时钟触发重新计算。
- 影响：页面打开后直播时长保持不变。
- 方案：直播中启用按分钟更新的单一计时器，状态结束或组件卸载时清理。格式化逻辑保持纯函数。
- 验收：直播中时长每分钟更新；离线状态不创建计时器；反复挂载卸载不残留定时任务。

### UP-006 隐藏顶层区块时彻底移除布局间距

- 状态：已完成
- 现状：`src/apps/user-page/block/BlockPageRenderer.vue` 仍为隐藏区块输出顶层包装元素，页面 flex gap 因此保留空白。
- 影响：隐藏内容后页面出现无法解释的垂直间距。
- 方案：渲染前生成 `visibleBlocks`，顶层和嵌套区块都只遍历可见节点。隐藏逻辑只保留一处。
- 验收：隐藏任意连续区块都不留下间距、边框或占位；组内隐藏行为一致。

### UP-007 收紧外部 iframe 与自定义媒体来源

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/FeedbackBlock.vue` 和 `src/apps/user-page/block/blocks/MusicPlayerBlock.vue` 可以接受较宽泛的 HTTPS 地址，iframe 缺少完整的 `sandbox`、`title`、`referrerpolicy` 和最小 `allow` 配置。
- 影响：与 `DESIGN.md` 中“服务商白名单和固定 iframe 来源”的安全边界不一致，也影响可访问性与隐私。
- 方案：
  1. 每类嵌入声明允许的服务商、域名、路径格式和查询参数。
  2. URL 解析使用 `URL` API，拒绝非白名单 host、用户名密码、危险协议和重定向式参数。
  3. 由服务商适配器生成最终 iframe `src`，不直接透传用户输入。
  4. 为 iframe 设置明确 `title`、最小 `sandbox`、`referrerpolicy="no-referrer"` 和必要的 `allow`。
  5. 编辑器预览与公开页面共用同一验证器。
- 验收：未登记来源无法保存或发布；合法来源可正常播放或提交；每个 iframe 均有可访问名称和最小权限；增加对应单元测试。

## 4. P1：数据一致性、性能与可维护性

### UP-008 消除异步请求竞态

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/VideoListBlock.vue` 和 `src/apps/user-page/block/blocks/StreamScheduleBlock.vue` 在用户快速修改配置时，没有请求身份或取消机制，旧响应可能覆盖新结果。
- 方案：使用 `AbortController` 或递增请求标识，仅提交最后一次请求的结果。日程数据按用户维度缓存完整结果，`weeksCount` 只在本地切片，不重复请求同一数据。
- 验收：快速切换用户、筛选条件或周数时不出现旧数据回写；组件卸载后不再更新状态；相同来源的多个区块共享请求结果。

### UP-009 校验全局唯一的区块 ID

- 状态：已完成
- 现状：`src/apps/user-page/block/schema.ts` 校验节点结构，但没有递归保证整页区块 ID 唯一。
- 影响：编辑器选择、拖放、分组、错误定位和未来的锚点功能可能命中错误节点。
- 方案：一次深度遍历收集所有顶层与嵌套 ID，发现重复立即返回包含冲突路径的校验错误。隐藏节点也必须参与结构和 ID 校验。
- 验收：任意层级重复 ID 都无法保存或发布；错误信息能定位两个冲突节点；复制区块始终生成新 ID。

### UP-010 公开渲染器按需加载区块

- 状态：已完成
- 现状：`src/apps/user-page/block/registry.ts` 同步导入全部区块组件，访问简单页面也会携带未使用区块代码。
- 方案：将 registry 拆成共享元数据、编辑器注册表和公开渲染注册表。公开渲染使用异步组件；编辑器是否预加载由实际交互决定。
- 验收：只使用基础文本区块时，不下载视频、音乐、日程和反馈实现；异步区块有稳定占位和加载失败状态；首屏不发生明显布局跳动。
- 度量：记录改造前后公开用户页入口 chunk、实际路由依赖和首屏请求数，设置持续构建体积预算。

### UP-011 删除玻璃与非玻璃模式的重复渲染分支

- 状态：已完成
- 现状：`src/apps/user/pages/UserPageEntryView.vue` 为玻璃效果和普通效果重复维护整段页面主体。
- 影响：状态、错误处理和布局修改需要同步两份模板，容易产生行为差异。
- 方案：抽取唯一的 `PageContent` 渲染路径，玻璃效果仅作为容器 class、CSS 变量或单层包装差异。
- 验收：页面主体只保留一份模板；切换玻璃效果不改变数据和交互行为。

### UP-012 替换手写富文本清理器

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/RichTextBlock.vue` 内维护了较长的手写 HTML 和样式清理逻辑，缺少专项绕过测试。
- 影响：协议、SVG、事件属性、CSS URL 和编码变体容易遗漏；前后端规则可能逐渐不一致。
- 方案：使用成熟、浏览器侧可用的清理库，并配置严格 allowlist。前端负责即时预览安全，后端继续作为最终边界；禁止把前端清理当作唯一防线。
- 验收：覆盖链接、图片、事件属性、SVG、危险协议、CSS 表达式和编码绕过测试；前后端允许能力有明确交集；合法内容不被意外破坏。

### UP-013 建立页面级数据缓存

- 状态：已完成
- 现状：多个同来源区块可能分别请求相同用户的视频、直播状态或日程数据。
- 方案：在页面运行时层提供按资源键缓存的轻量查询函数，缓存状态只包含 loading、data、error 和失效时间，不引入复杂响应式编排。
- 验收：同一页面相同资源仅请求一次；重试、切换用户和手动刷新可以明确失效；错误不会永久缓存。

### UP-014 增加图片加载与失败状态

- 状态：已完成
- 现状：图片区块和画廊缺少一致的 loading、empty、error 反馈，部分图片未使用懒加载和异步解码。
- 方案：统一图片资源组件或最小状态逻辑，非首屏图片使用 `loading="lazy"` 和 `decoding="async"`，保留明确宽高或宽高比，失败时显示与主题一致的占位。
- 验收：慢网和无效图片地址不会出现空白或大幅布局跳动；首屏关键图不被错误延迟；替代文本可配置并在编辑器中提示。

### UP-015 明确配置版本迁移策略

- 状态：已完成
- 现状：已有少量字段归一化逻辑，但没有集中、可测试的配置版本迁移入口。
- 方案：发布配置包含明确版本；读取时按版本顺序执行纯函数迁移，迁移后只保留最新结构，不在渲染组件中兼容旧字段。
- 验收：历史样本可一次迁移到当前版本；迁移幂等；渲染组件不包含旧字段 fallback；迁移有固定样例测试。

## 5. P2：公开页面用户体验与视觉优化

### UP-016 使用真实标题语义

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/HeadingBlock.vue` 的层级主要体现在 class 和字号，未完整映射为 `h1`、`h2`、`h3` 等语义元素。
- 方案：根据受限的 level 值动态渲染真实标题标签，并限制一页主要标题的使用规则。
- 验收：标题层级可被辅助技术识别；视觉样式与标签语义解耦；非法层级无法保存。

### UP-017 完善链接与图标的可访问名称

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/SocialLinksBlock.vue` 隐藏文字后，图标链接可能没有可访问名称；新窗口行为也没有明确提示。
- 方案：使用平台名或用户自定义名称生成 `aria-label` 与 `title`，统一补充 `rel="noopener noreferrer"`，必要时在可访问名称中说明新窗口打开。
- 验收：仅图标模式通过可访问性树检查；键盘焦点清晰；链接名称不依赖图标形状。

### UP-018 将日历复制操作改为完整按钮交互

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/StreamScheduleBlock.vue` 使用可点击 div 复制 ICS 内容，没有完整键盘语义，也没有可靠的成功或失败反馈。
- 方案：改为真实 button，等待 clipboard Promise，使用短暂状态或消息提示反馈结果；失败时提供可理解的替代操作。
- 验收：Enter 和 Space 均可操作；成功与失败都有反馈；重复点击不会产生错乱状态。

### UP-019 系统处理窄屏布局

- 状态：已完成
- 涉及组件：`src/apps/user-page/block/blocks/ImageGalleryBlock.vue`、`CountdownBlock.vue`、`VideoListBlock.vue`、`BiliInfoBlock.vue`、公开用户页侧栏与内容容器。
- 现状：画廊最多固定 12 列；倒计时四个大数字可能超宽；视频列表缺少完整窄屏规则；B 站信息紧凑模式拥挤；移动端仍保留较固定的侧栏空间。
- 方案：优先使用容器宽度决定布局，而不是只依赖视口宽度。
  - 画廊在窄容器下自动收敛为 1 至 2 列。
  - 倒计时使用稳定网格和紧凑字号，极窄容器允许两行排列。
  - 视频卡片根据最小卡片宽度自动换列。
  - B 站信息在窄宽度下将统计、关注按钮和身份信息分层排列。
  - 公开页导航在手机上评估抽屉或底部入口，不持续挤占正文宽度。
- 验收：320、375、768、1024 和宽桌面尺寸下无横向滚动、文本遮挡或控件溢出；区块放入窄列时仍可用。

### UP-020 尊重减少动态效果偏好

- 状态：已完成
- 现状：跑马灯、画廊自动播放、悬停位移和部分过渡没有统一响应 `prefers-reduced-motion`。
- 方案：减少动态效果模式下停止跑马灯与自动轮播，移除非必要位移和缩放，保留必要的短时状态反馈。
- 验收：系统开启减少动态效果后不存在持续移动内容；页面功能仍可通过手动控件使用。

### UP-021 统一主题变量和自定义颜色对比度

- 状态：已完成
- 现状：`src/apps/user-page/block/blocks/TagsBlock.vue`、`StreamScheduleBlock.vue` 及少数组件仍存在硬编码颜色或不一致的背景文字组合；自定义标签色无法保证前景对比度。
- 方案：原生元素统一使用 `--vtsuru-fg`、`--vtsuru-fg-muted`、`--vtsuru-bg`、`--vtsuru-bg-muted`、`--vtsuru-bg-elevated`、`--vtsuru-border`、`--vtsuru-brand-soft` 和 `--vtsuru-brand-tint`。自定义颜色通过亮度计算选择前景色，无法满足最低对比度时限制颜色范围。
- 验收：明暗主题和自定义背景下文字、边框、悬停、选中、禁用状态可辨认；不把 Naive UI 内部 `--n-*` 状态变量用作普通内容背景。

### UP-022 统一公开页面语言

- 状态：已完成
- 现状：页面混用 `SCHEDULE`、`WEEK`、`TODAY`、`COPY`、`DAYS`、`HRS`、`MINS`、`SECS` 与中文文案。
- 方案：默认全部使用中文；若项目确定需要多语言，则集中为轻量文案表，不允许各区块自行硬编码语言。
- 验收：同一语言环境下所有区块文案一致；日期、时长和数字格式遵循同一 locale。

### UP-023 修复画廊控件与说明文字重叠

- 状态：已完成
- 现状：画廊底部 caption、分页圆点和控制区可能占用同一视觉区域。
- 方案：为说明文字和分页控制分配独立布局区域；图片覆盖层只承载确实需要叠加的内容；窄屏时缩短或折行说明。
- 验收：长说明、多页圆点、深浅图片背景和窄屏下均无重叠；控制按钮具备键盘焦点和明确名称。

### UP-024 补充动态内容的状态提示

- 状态：已完成
- 范围：直播状态、画廊、视频列表、日程、贡献页面。
- 方案：统一最小的 loading、empty、error、retry 视觉语言；直播状态变化使用适度的 `aria-live`；公开页错误保持简洁，详细错误写入日志。
- 验收：所有远程数据区块都能区分加载中、无数据和加载失败；错误状态不暴露接口地址、schema 路径或内部异常。

### UP-025 优化玻璃效果和背景性能

- 状态：已完成
- 现状：多层卡片同时使用 blur 或 backdrop-filter 时，在移动设备和复杂背景上成本较高。
- 方案：玻璃效果尽量集中到单层页面容器；内部卡片使用半透明语义色而非重复模糊。低性能或减少透明度偏好下关闭模糊并提高实色对比度。
- 验收：中端移动设备滚动无明显持续卡顿；关闭模糊后信息层级仍清楚；背景不会降低正文可读性。

## 6. P2：编辑器体验优化

### UP-026 重组顶部工具栏

- 状态：已完成
- 现状：`src/apps/manage/pages/UserPageBuilderView.vue` 顶部同时放置保存、发布、回滚、资源、布局、全局样式、清空、状态和自动保存提示，信息密度过高。
- 方案：
  - 主操作固定为保存和发布。
  - 撤销、重做使用标准图标按钮和 tooltip。
  - 回滚、清空等低频或高风险操作进入更多菜单，并使用确认对话框。
  - 保存状态固定占位，避免文字变化推动布局。
  - 页面、区块、资源和全局样式作为清晰的视图或面板切换。
- 验收：常用操作一眼可见；低频操作不占用主工具栏；窗口变窄时按钮不挤压或换成无法识别的文字。

### UP-027 扩展预览模式

- 状态：已完成
- 现状：编辑器以手机预览为主，缺少平板和桌面容器宽度验证，也缺少直接打开真实公开路由的完整预览。
- 方案：增加手机、平板、桌面分段控制；预览容器使用稳定宽高约束；提供“在新窗口预览”命令，使用草稿预览凭据访问真实路由。
- 验收：三种尺寸切换不丢失编辑状态；真实路由预览与发布后渲染路径一致；预览不会意外公开草稿。

### UP-028 改善校验错误定位

- 状态：已完成
- 现状：复杂页面校验失败时，用户需要自行寻找具体区块和字段。
- 方案：错误对象包含 block ID、字段路径和用户可读文案；点击错误直接选中区块、展开对应表单并聚焦字段。内部 schema 路径只用于开发日志。
- 验收：发布失败后最多一次点击即可到达问题字段；多个错误可以逐项处理；隐藏或分组区块也能正确展开定位。

### UP-029 增加区块库搜索与起始模板

- 状态：已完成
- 现状：区块类型增加后，仅依赖分类会逐渐降低查找效率；新用户需要从空白页逐项搭建。
- 方案：区块库增加名称和关键词搜索；提供少量经过验证的起始模板，如直播主页、作品展示、日程页。模板只生成普通区块配置，不引入独立运行逻辑。
- 验收：搜索可匹配名称与常用别名；模板插入后可完全编辑；模板升级不影响已创建页面。

### UP-030 统一确认、输入和反馈组件

- 状态：已完成
- 现状：部分页面或区块管理操作仍使用 `window.confirm`、`window.prompt`，与主界面视觉和键盘体验不一致。
- 方案：使用 Naive UI dialog、popconfirm、modal 和 message；删除原生弹窗分支。危险操作明确展示目标名称和影响范围。
- 验收：所有编辑器确认流程主题一致、可键盘操作；取消不会产生部分修改；危险操作不可因连续点击重复执行。

### UP-031 加强资源管理反馈

- 状态：已完成
- 方案：上传中展示逐项进度和失败原因；资源被使用时显示引用数量；删除前列出影响；复制资源链接提供明确反馈；图片资源展示尺寸和文件大小。
- 验收：用户能识别仍在上传、上传失败、未使用和正在引用的资源；错误不会只显示通用失败。

## 7. P1/P2：架构整理

### UP-032 将区块能力集中到 registry

- 状态：已完成
- 现状：区块默认值、校验、编辑字段、公开组件、分类和显示名称分散在多个大文件中。
- 目标结构：每种区块只维护一份定义，至少包含 `type`、`defaultProps`、`validate`、`editor`、`viewer`、`category` 和 `keywords`。
- 方案：先为一个简单区块建立目标结构并验证，再按类型迁移；迁移完成后删除旧 switch 和重复映射，不保留双轨兼容层。
- 验收：新增区块无需同时修改大型 switch；缺少编辑器、校验器或渲染器时在开发阶段立即报错。

### UP-033 分解超大文件

- 验收：主要组件保持单一职责；不以转发 props 的空壳组件制造层级；重复逻辑被删除；单文件原则上控制在 500 行以内。

### UP-034 统一区块远程数据接口

- 状态：已完成
- 方案：视频、日程、直播和贡献模块统一接收页面运行时提供的数据访问器，组件不自行拼接重复请求和错误处理。接口保持简单 async/await，不引入复杂流式编排。
- 验收：请求、取消、缓存和错误映射只有一个实现入口；区块组件可以使用固定数据进行测试。

### UP-035 明确隐藏区块校验规则

- 状态：已完成
- 现状：隐藏区块可能跳过部分 props 校验，重新显示时才暴露旧配置问题。
- 方案：隐藏节点始终校验结构、类型、ID 和安全字段；仅在产品明确允许时跳过“当前展示必填”规则，并把规则写入 schema 定义。
- 验收：隐藏内容不能携带非法 URL、重复 ID 或未知类型进入发布配置；重新显示不会立即导致页面失效。

## 8. P3：SEO 与可观测性

### UP-036 使用自定义页面元信息

- 状态：已完成

### UP-038 建立性能预算

## 12. 完成定义

单个改进项只有同时满足以下条件才可标记完成：

- 实现已删除被替代的旧逻辑，不保留无用兼容分支。

## 13. 暂不纳入本轮的内容

- 不新增通用低代码平台能力。
- 不开放任意 HTML、JavaScript 或任意 iframe。
- 不为了兼容废弃配置继续扩大渲染器分支。
- 不引入复杂状态机库、响应式流或重量级页面构建框架。
- 不在完成公开页面正确性前扩充大量新区块类型。

这些边界用于保持用户页功能聚焦，优先把现有能力做稳定、清晰和易维护。
