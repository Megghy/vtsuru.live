# 用户自定义页面第二阶段改进计划

> 审查日期：2026-07-28
>
> 适用范围：用户页面构建器、公开用户页区块、草稿预览和直接依赖
>
> 文档状态：实施中
>
> 上一阶段记录：`IMPROVEMENT_PLAN.md`

## 1. 目标

本阶段不再扩展成通用低代码平台，而是集中解决以下问题：

1. 保证撤销、加载、保存、发布和预览状态可信，不允许界面与实际保存配置脱离。
2. 让编辑器在宽屏、窄屏和触摸设备上都能完成完整操作。
3. 建立预览画布与区块树的双向操作，减少在多个面板之间反复定位。
4. 优先接入 VTSURU 已有站内功能，只增加不能被现有区块合理组合替代的类型。
5. schema、默认值、编辑器、预览和公开渲染必须同步完成，不保留无效配置或兼容分支。

## 2. 当前基线

### 2.1 已有区块

本阶段审查开始时共有 29 种区块；完成二维码后现有区块为 30 种：

- 基础布局：布局容器、标题、文本、富文本、分割线、间距、页脚。
- 状态内容：提示框、走马灯、倒计时、标签、时间轴、问答、引用。
- 图片媒体：图片、图片组、嵌入视频、视频列表、音乐播放器。
- 导航互动：链接列表、单按钮、按钮组、社交链接、留言/提问、支持/赞助。
- 用户数据：个人信息、直播状态、直播日程、B站数据卡片。

现有静态内容覆盖已经足够。二维码已作为独立工具型区块补充；其他新增类型优先连接站内动态能力。

### 2.2 已有编辑能力

- 多页面、页面复制、页面重命名和导航排序。
- 区块拖拽、多选、分组、隐藏、复制粘贴和持久化剪贴板。
- 撤销重做、自动保存、手动保存、发布、回滚和资源管理。
- 手机、平板、桌面预览与真实页面草稿预览。
- 发布校验、错误区块标记和错误定位。

### 2.3 优先级

| 优先级 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 | 可能保存错误配置、覆盖服务端数据或让界面状态失真 | 阻断后续功能扩展 |
| P1 | 明显影响主要编辑流程、预览准确性或窄屏可用性 | P0 后连续完成 |
| P2 | 提升编辑效率、一致性和可访问性 | 核心流程稳定后完成 |
| P3 | 新增动态区块和长期增强能力 | 按本文顺序实施并观察使用量 |

## 3. 第一阶段：状态正确性与数据保护

### PH2-001 修复撤销和重做后的页面引用

- 状态：已完成
- 问题：历史恢复会替换整个 `settings`，`currentPage` 却保存旧对象引用。撤销后属性面板可能继续修改旧对象，预览和最终保存配置可能不一致。
- 方案：`currentPage` 必须由 `settings + currentKey` 派生，或在每次历史恢复后统一重新绑定；同时清理已经不存在的选区和悬停状态。
- 验收：主页和子页面在撤销、重做、切换页面后，属性修改始终落入当前 `settings`；保存内容与预览一致；增加自动化回归测试。

### PH2-002 建立编辑器初始化状态机

- 状态：已完成
- 问题：加载失败后仍会显示默认配置和保存、发布操作，存在误覆盖服务端配置的风险。
- 方案：使用 `loading / ready / error` 三态；只有 `ready` 渲染工作区并启用写操作；错误状态只显示原因和重试入口。
- 验收：断网、超时、500 和非法响应下均不能编辑、保存或发布默认配置；重试成功后恢复正常工作区。

### PH2-003 统一本机草稿与服务端草稿状态

- 状态：已完成
- 问题：修改会立即写入本机草稿，但离开提示称修改会丢失；自动保存开关实际只控制服务端同步；同步失败只有控制台错误且不会主动重试。
- 方案：明确显示 `本机已保存 / 正在同步 / 服务端草稿已同步 / 同步失败 / 尚未发布`；离开提示准确说明本机恢复与服务端同步的差别；同步失败提供持久重试入口和有限延迟重试。
- 验收：断网编辑、恢复网络、关闭自动保存和离开页面时，提示与实际行为完全一致；保存状态支持屏幕阅读器播报。

### PH2-004 改进发布失败与版本状态

- 状态：已完成
- 问题：确认发布时弹窗先关闭，请求失败后只留下瞬时消息；已加载的草稿、已发布版本和回滚版本没有形成清晰的版本入口。
- 方案：发布完成前保持弹窗；失败时保留错误和重试按钮；状态入口显示当前编辑基础版本；回滚前允许只读预览上一个版本。
- 验收：发布失败不会丢失上下文；用户能明确区分本机修改、服务端草稿、当前线上版本和可回滚版本。

### PH2-005 结构化校验问题

- 状态：已完成
- 问题：错误定位依赖解析中文错误文本和数组下标，无法解析时点击错误没有反馈。
- 方案：校验直接返回 `{ message, pageKey, blockId, fieldPath, severity }`；编辑器常驻显示问题数量，并在具体字段下展示错误。
- 验收：每个可定位错误都能切换到正确页面、展开父布局、选中区块并聚焦字段；无法定位的问题也有明确反馈。

## 4. 第二阶段：预览准确性与工作区布局

### PH2-006 统一容器响应式规则

- 状态：已完成
- 问题：手机预览缩小的是内部容器，但布局和标题区块仍使用浏览器级媒体查询，宽屏电脑上的手机预览不准确。
- 方案：区块内部统一使用容器查询；固定格式元素设置稳定宽高和响应式约束。
- 验收：内嵌手机预览、真实手机页面和缩窄浏览器窗口得到相同布局结果。

### PH2-007 对齐预览与真实页面数据

- 状态：已完成
- 问题：构建器预览没有加载完整 B 站资料，动态区块可能显示空状态，而真实页面可以正常展示。
- 方案：复用公开页面的数据加载逻辑；无法加载的动态数据使用明确的编辑器占位，不伪装成真实空数据。
- 验收：B站卡片、直播状态、日程和视频等区块在构建器与公开页的数据状态一致。

### PH2-008 重构为自适应工作区

- 状态：已完成
- 宽屏：页面、区块、预览、属性四列横向常驻；页面栏可收起为图标导航。
- 中屏：页面与区块在第一列切换，预览和属性编辑分别常驻第二、三列；保持电脑端横向边看边改。
- 小屏：页面、区块和预览作为主视图切换，属性编辑常驻下半区；保存和发布固定在易触达位置。
- 技术要求：使用 `ResizeObserver` 监听工作区实际宽度，使用 `100dvh`，不能只监听浏览器窗口。
- 验收：320、375、768、1024、1440 像素下没有不可访问的面板、横向裁切或文字重叠。

### PH2-009 简化主视图结构

- 状态：已完成
- 问题：四列面板在多层 `NSplit` 中重复渲染，布局逻辑和用户配置都过于复杂。
- 方案：使用统一 `BuilderPaneHost` 按面板 ID 渲染；提供内容优先、预览优先、紧凑等布局预设；重置操作同时支持重置顺序和列宽。
- 验收：面板定义只保留一份；自适应切换不销毁编辑状态；不保留旧的重复渲染分支。

## 5. 第三阶段：画布与编辑交互

### PH2-010 预览画布双向选择

- 状态：已完成
- 功能：点击预览区块选中；选中区块持续高亮；区块树、属性面板和预览互相滚动定位。
- 模式：提供选择模式和交互模式，避免编辑时误打开链接；隐藏区块在编辑预览中显示半透明占位。
- 验收：鼠标和触摸设备都能从预览进入编辑；公开渲染器不包含编辑器控件。

### PH2-011 完整键盘操作

- 状态：已完成
- 快捷键：撤销、重做、保存、复制、粘贴、创建副本、删除。
- 树操作：上下键移动焦点，左右键展开收起，Enter 或 Space 选择；快捷键跳过输入框、文本域和富文本区域。
- 可访问性：区块树使用正确的 tree/treeitem 语义和 roving tabindex；拖拽结果通过状态区域播报。
- 验收：不使用鼠标可以完成区块选择、排序替代操作、属性编辑、保存和发布。

### PH2-012 改善多选属性面板

- 状态：已完成
- 未选择：显示添加区块和起始模板入口。
- 单选：显示完整属性。
- 多选：显示数量并允许批量设置显示、边框、背景，以及复制、删除和成组。
- 验收：不再始终显示错误的“请选择一个区块”提示；多选时属性栏不为空。

### PH2-013 明确拖拽落点和触摸移动

- 状态：已完成
- 拖拽落点：插入上方、插入下方、移入布局、与目标成组必须使用不同的可视提示。
- 触摸替代：提供“移动到”菜单，不要求精确拖动小尺寸手柄。
- 验收：普通排序不会误触发分组；触摸设备可以不拖拽完成移动和分组。

### PH2-014 按当前选区插入区块

- 状态：已完成
- 规则：选中普通区块时插入其下方；选中布局时明确选择加入布局或插到布局下方；无选区时追加到末尾。
- 验收：新增区块出现在用户预期位置，并自动完成树和预览定位。

### PH2-015 修正起始模板语义

- 状态：已完成
- 空页面：直接应用模板。
- 非空页面：显示模板内容，并选择追加或替换。
- 扩展：允许把当前选中区块保存为个人模板。
- 验收：重复点击不会在没有提示的情况下不断追加同一套区块。

### PH2-016 统一重复项目编辑器

- 状态：已完成
- 适用：链接、社交链接、视频、标签、时间轴、问答、支持平台和后续图文卡片。
- 功能：稳定项目 ID、拖拽排序、复制、折叠编辑、删除确认；窄栏下字段改为纵向排列。
- 验收：所有重复项目使用同一交互模式，删除项目不会导致其他输入框状态错位。

### PH2-017 合并重复页面设置入口

- 状态：已完成
- 方案：页面栏只负责切换、排序和可见状态摘要；页面名称、路径、说明和其他详细设置集中到属性面板。
- 验收：同一字段只存在一个主要编辑入口。

### PH2-018 增加区块显示条件

- 状态：已完成
- 首版条件：始终显示、仅直播中、仅未开播、指定日期范围、仅桌面、仅移动端。
- 约束：使用简单声明式条件，不引入表达式语言。
- 验收：编辑预览可模拟条件；公开页不会渲染不符合条件的区块和多余间距。

### PH2-019 处理属性依赖关系

- 状态：已完成
- 问题：属性面板可能允许配置渲染器不会使用的组合，例如紧凑直播卡片曾允许开启但不显示封面。
- 方案：依赖项不适用时隐藏或禁用对应控件；schema、编辑器和渲染器共享能力定义。
- 验收：不存在“控件可以保存，但公开页永远不生效”的配置。

## 6. 第四阶段：新增区块

### PH2-020 站内功能入口 `featureNav`

- 状态：已完成
- 优先级：第一新增类型。
- 功能：根据用户已启用能力自动展示歌单、提问箱、签到排行、积分兑换、视频征集、论坛和直播日程；允许排序和隐藏单项。
- 验收：只展示实际可用功能；内部路由由系统生成，不要求用户手填链接。

### PH2-021 歌单与点歌 `songList`

- 状态：已完成
- 样式：紧凑和完整两种形态。
- 功能：搜索歌曲、展示可点状态、跳转完整歌单；确认接口和权限边界后再提供区块内点歌。
- 验收：不直接嵌入现有完整页面；远程查询有加载、空、失败和重试状态。

### PH2-022 通用图文卡片列表 `cardList`

- 状态：已完成
- 场景：作品集、委托项目、服务菜单、周边、合作伙伴和推荐内容。
- 项目字段：图片、标题、正文、标签、主按钮和次按钮。
- 验收：复用资源选择器和统一重复项目编辑器；网格与列表在窄屏下正确重排。

### PH2-023 二维码 `qrcode`

- 状态：已完成
- 功能：输入文本或链接生成二维码；支持尺寸、前景色、背景色、纠错等级、边距和可选标题。
- 交互：可复制内容、打开链接和下载二维码；非链接内容不显示打开按钮。
- 技术：复用现有 `qrcode.vue`，不请求第三方二维码服务。
- 安全：链接执行现有 URL 校验；公开页不允许脚本协议。
- 验收：明暗主题和透明背景下保持可扫描；手机与桌面可正常扫码；下载结果与页面一致。

### PH2-024 紧凑签到榜 `checkInRanking`

- 状态：已完成
- 功能：展示前三名或前十名和完整页面入口，不复制完整筛选分页界面。
- 验收：尊重用户功能开关和公开权限，远程状态完整。

### PH2-025 精选积分商品 `featuredGoods`

- 状态：已完成
- 首版：展示 3 至 6 个商品、价格、库存状态并跳转积分页，不在区块内直接兑换。
- 验收：未登录和无权限状态明确，商品失效不会留下错误操作入口。

### PH2-026 当前视频征集 `videoCollect`

- 状态：已完成
- 功能：展示正在进行的征集主题、截止信息和投稿入口。
- 验收：活动结束后自动移除或显示结束状态，不依赖用户手动更新静态文案。

### PH2-027 自动页面目录 `sectionNav`

- 状态：已完成
- 功能：根据标题区块生成锚点导航并高亮当前章节。
- 验收：标题 ID 稳定且全页唯一，键盘和浏览器前进后退行为正确。

### PH2-028 当前播放与点歌队列 `nowPlaying`

- 状态：已完成
- 前提：确认公开接口、隐私边界和实际使用需求。
- 首版：只展示当前歌曲、队列数量和完整点歌页入口。

### PH2-029 后续候选动态区块

- 状态：已完成（评估）
- 候选：最新论坛讨论、B站动态、投票、抽奖和留言墙。
- 约束：需要新增后端、审核、限流或不稳定第三方数据源的类型，必须先用实际需求证明收益。

评估结论：

| 候选 | 当前基础 | 结论 | 进入实现前的条件 |
| --- | --- | --- | --- |
| 最新论坛讨论 | 已有公开 `get-forum`、分页 `get-topics`、论坛查看权限和完整讨论区路由 | 下一阶段首选，只做只读摘要和完整讨论区入口 | 查询层直接返回错误，不复用会吞错的 Pinia 页面方法；后端权限拒绝必须显示明确状态 |
| B站动态 | 当前只有用户资料与视频索引，没有稳定的动态聚合接口 | 暂不实施 | 后端提供受控缓存、限流、字段清洗和上游失败状态，不允许浏览器直接请求不稳定第三方接口 |
| 投票 | 弹幕投票已有 OBS `obs-data`，但没有用户页功能开关或面向公开页面的稳定契约 | 暂不实施 | 增加独立功能开关、公开活动状态接口、结果公开策略和活动结束语义 |
| 抽奖 | 直播抽奖参与者与历史主要保存在主播本机，现有接口服务于管理流程 | 不实施 | 只有形成服务端公开抽奖会话、隐私规则和结果保留策略后才重新评估 |
| 留言墙 | 现有论坛、提问箱、反馈区块已覆盖发布、审核和跳转场景 | 不新增独立类型 | 只有出现无法由现有能力组合解决的公开展示需求，并具备审核、举报和限流方案后才重新评估 |

本阶段不继续增加动态区块。下一阶段若实施“最新论坛讨论”，首版仅展示标题、作者、回复数、更新时间和完整讨论区入口，不在用户页内复制发帖、回复、点赞或管理操作。

### PH2-030 工作区直接调整与固定操作区

- 状态：已完成
- 列宽：宽屏和中屏使用可拖动分隔线直接调整；分隔线支持触控和左右方向键，列宽自动限制在可用范围并持久化。
- 页面栏：宽屏和中屏可收起为 56 像素图标导航；重新展开恢复此前宽度，收起状态独立持久化。
- 区块栏：添加区块、起始模板和保存模板使用带提示的图标按钮固定在卡片 header；批量操作固定在区块树上方，只有区块树滚动；添加菜单限制在视口内独立滚动。

- 契约策略：前端继续执行即时字段校验以保证编辑反馈和错误定位，后端在发布边界执行权威校验；不把编辑过程改成逐次请求后端。规则继续增长时，将区块契约改为由同一份 JSON Schema 生成前后端验证代码，避免长期手工维护两套定义。
- 验证：后端解决方案构建通过，`VTsuru.Tests` 共 72 项测试通过。

## 7. 不新增独立类型的内容

- 公告栏：使用提示框、富文本或走马灯。
- 联系方式：使用社交链接、链接列表或按钮组。
- 感谢语录：使用引用区块。
- 价格表、赞助墙和简单商品展示：优先使用图文卡片列表。
- 自定义 HTML、JavaScript 和任意 iframe：不开放。

## 8. 实现结构要求

1. 新增区块必须同时完成类型、共享定义、默认值、校验、图标、异步渲染器、属性编辑器和迁移判断。
2. 区块内部响应式优先使用容器查询，不能依赖构建器外层浏览器宽度。
3. 远程数据统一使用页面运行时查询工具，具备取消、缓存、加载、空、失败和重试状态。
4. 列表型属性统一复用一个有稳定 ID 的编辑组件，不继续复制基于数组下标的表单。
5. 主编辑视图应删除重复面板渲染，不在旧结构上继续叠加条件分支。
6. 所有图标按钮必须有工具提示和可访问名称；动画尊重减少动态效果设置。
